# W2 — accessibility

**Method.** axe-core (WCAG 2.0/2.1 A and AA tags, the same set `e2e/a11y.spec.ts` uses) on all 43 routes × 2 themes × 2 devices (172 runs, production build, demo mode). The keyboard entry path and dialog behaviour were checked by hand (`01_UX.md`).

**Result.** 168 of 172 runs are clean. Three rule types appear on four routes:

| Rule (axe impact) | Route(s) | Element | Runs |
|---|---|---|---|
| `label` (critical) | `/demo/imports` | the CSV `input[type=file]`, which is `sr-only` but still focusable and has no label | 4/4 |
| `color-contrast` (serious) | `/demo/inbox` (light) | "Drafted by Huntloop" chip: `text-ai` at 12 px (`inbox/InboxView.tsx:351`, `:537`) | 2/4 |
| `color-contrast` (serious) | `/demo/companies` (dark, desktop) | the `text-brand` link in column 5 of the company table, 3 nodes | 1/4 |
| `scrollable-region-focusable` (serious) | `/demo/intelligence` (`#main`); `/demo/performance/report` (mobile: the `.overflow-x-auto` table wrapper) | a scrolling region that keyboard users cannot focus to scroll | 6 |

None of these four routes is in `e2e/a11y.spec.ts`, which checks 5 pages (landing, sign-in, dashboard, opportunity list, kitchen sink), plus the jump palette and two themed contrast checks. Every violation found here sits outside that list.

## Findings

### [Medium] A11Y-301: Four app screens fail WCAG A/AA checks, and the automated gate covers only 5 of 43 routes
- Confidence: CONFIRMED (axe, 172 runs).
- Where: as in the table above.
- Impact:
  - **Imports:** a screen-reader user tabbing through the form hits an unnamed file control before "Choose a file". That is an extra, unlabelled tab stop.
  - **Inbox:** the provenance chip ("Drafted by Huntloop") is the trust signal on the approval queue and fails contrast in light mode.
  - **Companies (dark):** the table link fails contrast.
  - **Intelligence and the performance report:** keyboard users cannot scroll these regions.
- Root cause: the a11y suite samples layouts ("one page per distinct layout"), but these components appear only on the pages it skips.
- Fix:
  1. File input: `tabIndex={-1}` plus `aria-hidden`, or `aria-label="CSV file"`. The visible button is the control (`imports/ImportForm.tsx:138-146`).
  2. Raise `text-ai` to meet 4.5:1 at 12 px on the light surface, or use 13 px semibold with a checked ratio.
  3. Check `text-brand` on the dark table background.
  4. Add `tabIndex={0}` and an accessible name to the scroll containers.
  5. Extend `e2e/a11y.spec.ts` to every org route (the sweep took 2.3 minutes for all 172 runs).
- Acceptance: the same sweep reports zero violations, and the spec covers every route under `/demo/*`.
- Effort: S · Mechanizable: yes (extend the spec) · Status: New

## Checked, fine
- Skip link, focus ring, landmarks, one `h1` per page (hand check).
- Native `<dialog>` modals: focus trap and Escape (code read; jump palette covered by e2e).
- `prefers-reduced-motion` is honoured in `globals.css` and `packages/ui/src/tokens.css`.
- No horizontal overflow at 375 px on any route.

## Not covered
- Screen-reader output (NVDA/VoiceOver) and the full tab order through each form: these need a person with the tools.
- WCAG 2.2 target size (not in the tag set the repo targets).
- Signed-in-only screens with real data (onboarding steps, settings with live integrations).
